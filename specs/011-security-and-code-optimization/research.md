## Decision 1: Safe Markdown Link Sanitization & Protocol Allowlisting

### Context
In `app/static/vendor/marked.min.js`, the regex markdown link replacer called `escapeHtml(url)` on URLs. However, `escapeHtml` only escapes `&`, `<`, `>`, `"`, and `'`. Malicious or hallucinated links with pseudo-protocols (e.g., `javascript:`, `data:`, `vbscript:`) would pass through intact, allowing XSS when clicked.

### Decision
Enforce a strict protocol allowlist directly in the link parsing logic of `app/static/vendor/marked.min.js`:
- Allow only `http://`, `https://`, `mailto:`, and relative paths starting with `/` (excluding `//`).
- Neutralize all other protocols to `#` (or reject rendering).
- Also sanitize the link anchor text `txt` via `escapeHtml(txt)` to prevent malformed nested markup.

### Alternatives Considered
- *Using full external DOMPurify library*: Rejected because the project has a strict zero-external-frontend-dependency philosophy, keeping files offline and completely bundled within `app/static/vendor`.
- *Stripping all links*: Rejected because users legitimately need clickable documentation and reference links generated by the AI models.

## Decision 2: Shared `httpx.AsyncClient` Connection Pool via FastAPI Lifespan

### Context
`OllamaClient` currently instantiates a new `httpx.AsyncClient` inside `check_health()`, `get_models()`, and `stream_generate()` on every invocation. With frontend health polling occurring every 15 seconds plus user streaming requests, this causes high socket churn, defeats TCP keep-alive reuse, and adds SSL/TCP handshake latency.

### Decision
Use FastAPI's standard `lifespan` context manager in `app/main.py` to initialize a single persistent `httpx.AsyncClient` on application startup and cleanly close it on shutdown. Inject this client into `OllamaClient` or manage it as a singleton.

### Alternatives Considered
- *Per-request client creation (current)*: Defeats connection pooling, risks socket exhaustion under load.
- *Unclosed global client*: Risks unhandled event loop shutdown errors and resource leaks upon container stop.

## Decision 3: Lightweight Liveness Probe for Upstream Health Checks

### Context
`OllamaClient.check_health()` currently sends `GET /api/tags`. When Ollama hosts multiple large models, `/api/tags` serializes a comprehensive JSON catalog including model layers, modified timestamps, and parameter sizes. Polling this every 15 seconds generates unnecessary CPU and memory overhead on Ollama.

### Decision
Target `GET /` on Ollama for `check_health()`. The Ollama HTTP daemon returns HTTP 200 with the plain text body `"Ollama is running"`. This provides instant liveness verification with zero catalog serialization.

### Alternatives Considered
- *Continuing with `/api/tags`*: Unnecessarily heavy for periodic liveness checks.
- *HEAD request to `/`*: Some reverse proxies or older Ollama versions might not support HEAD properly; `GET /` is universally supported and returns ~17 bytes.

## Decision 4: Input Validation for Model Identifiers

### Context
`app/models.py` defines `PromptRequest.model: str` with no character filtering or length boundaries. While Ollama handles missing models with a 404, malformed names (containing path separators, control characters, or oversized payloads) should be rejected at the API gateway boundary.

### Decision
Apply a strict Pydantic constraint:
- `min_length=1`
- `max_length=128`
- `pattern=r"^[a-zA-Z0-9_\-\./:]+$"`

### Alternatives Considered
- *Strict whitelist of currently loaded models*: Too rigid if models are pulled or loaded dynamically in Ollama without restarting the web UI.
- *No validation (current)*: Allows arbitrary string pass-through.

## Decision 5: Separation of Production vs Development Dependencies

### Context
`requirements.txt` currently lists `pytest>=8.0.0` and `pytest-asyncio>=0.23.0` alongside runtime packages (`fastapi`, `uvicorn`, `httpx`, `pydantic`). During container deployment, `pip install -r requirements.txt` is run inside the container, needlessly bloating the production image with test harnesses.

### Decision
Split into:
1. `requirements.txt`: Core runtime dependencies (`fastapi`, `uvicorn[standard]`, `httpx`, `pydantic`).
2. `requirements-dev.txt`: Development and testing dependencies (`-r requirements.txt`, `pytest`, `pytest-asyncio`).
Update packaging and deployment manifests to preserve backwards compatibility while keeping production payloads lean.

## Decision 6: Consistent Script Configuration & Workspace Hygiene

### Context
1. `scripts/test.sh` sets `CONTAINER_NAME="${1:-webui}"` while the entire deployment manager and lifecycle modules use `CONTAINER_NAME="e-webui-app"`.
2. A stray folder named `"tar -xzf '"` exists in the repository root due to a previous unquoted test invocation.

### Decision
1. Update `scripts/test.sh` to default to `e-webui-app`.
2. Delete the rogue `"tar -xzf '"` folder.
3. Review shell quoting across `scripts/lib/` to prevent similar unquoted globbing issues.
